# bf-614q — Add real-binary resolution with PATH shim-dir strip (shim.rs)

`bf-614q` is Stage 1.2b of the `bf-6d4` walking-skeleton split (split from
`bf-3pr`), scoped to `src/shim.rs`. It asks for `resolve_real_binary`:
return `cfg.real_binary` verbatim when `Some`, else PATH-lookup the real
`cargo` after **stripping gantry's own shim dir** (the parent of
`current_exe()`) so the search cannot re-resolve to the gantry shim itself,
and `Err` (never a silent self-fallthrough) when no cargo is found. No
exec/spawn — this bead only *produces* the resolved path.

This run produced **no source changes** — the function and every acceptance
test were already landed on this shared wip branch by the `bf-2cuz` umbrella's
child-bead chain (the `bf-2cuz` note, `notes/bf-2cuz.md`, documents the same
`resolve_real_binary` integration as "child 4 of the `bf-614q` auto-split").
`bf-614q` re-dispatches that identical work under the `bf-6d4` split; this run
verified the assembled state and closed the bead.

## What the bead asked for (src/shim.rs)

- `resolve_real_binary(cfg: &Config) -> Result<PathBuf, String>`:
  1. `cfg.real_binary == Some(path)` → `Ok(path)` with **no** PATH search.
  2. else → `shim_dir()?` (parent of `current_exe()`) → read `PATH` →
     `strip_dir_from_path(path, shim)` → `find_in_path("cargo", stripped)`;
     return its `Ok` or propagate its `Err`.
  - Never silently falls through to the gantry binary or `None`.
- No gate/refs/backend/local/runlog code; no exec/spawn.
